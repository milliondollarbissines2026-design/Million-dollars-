# OKX Trading Bot (EMA + RSI, спот, 5m)

Простой бот для спотовой торговли на OKX:
- Таймфрейм: **5 минут**
- Сигнал на вход: пересечение EMA9/EMA21 снизу вверх + RSI не в перекупленности
- Сигнал на выход: обратное пересечение EMA, либо стоп-лосс/тейк-профит по цене (проверяется каждые 30 сек)
- По умолчанию работает на **демо-счёте OKX** — без риска потери реальных денег

⚠️ **Это не финансовый совет.** Торговля криптовалютой связана с риском потери средств.
Обязательно протестируйте бота на демо-счёте в течение нескольких дней/недель, прежде чем
включать `DEMO_MODE=false`.

## 1. Получаем API-ключи OKX для демо-счёта

1. Зайдите на okx.com → в правом верхнем углу профиля включите **Demo Trading**.
2. В демо-режиме перейдите в **API Management** и создайте новый API-ключ
   (обычные "боевые" ключи для демо не подходят — там своя пара ключей).
3. Дайте права **Trade** + **Read**, сохраните `API Key`, `Secret Key`, `Passphrase`.

Когда решите перейти на реальную торговлю — создадите отдельные ключи в обычном (не демо) кабинете
и поменяете `DEMO_MODE` на `false`.

## 2. Заливаем код в GitHub

```bash
cd okx-trading-bot
git init
git add .
git commit -m "Initial commit: OKX trading bot"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
git push -u origin main
```

## 3. Деплой на Railway

1. Зайдите на railway.app → **New Project** → **Deploy from GitHub repo**.
2. Выберите репозиторий, который только что запушили.
3. Railway сам определит Python-проект по `requirements.txt` (Nixpacks) и запустит команду
   из `railway.json` (`python main.py`).
4. Откройте вкладку **Variables** проекта и добавьте переменные (минимум):
   - `OKX_API_KEY`
   - `OKX_SECRET`
   - `OKX_PASSPHRASE`
   - `DEMO_MODE=true`
   - остальные — по желанию, есть значения по умолчанию (см. `.env.example`)
5. Сохраните — Railway передеплоит сервис автоматически.

С этого момента **любой `git push` в ветку `main`** автоматически триггерит новый деплой на Railway —
это и есть связка GitHub + Railway (CI/CD из коробки, без дополнительной настройки).

## 4. Смотрим логи

Во вкладке **Deployments → View Logs** в Railway видно все действия бота: расчёт индикаторов,
сигналы, открытие/закрытие позиций.

## Параметры стратегии (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SYMBOL` | `BTC/USDT` | торговая пара (спот) |
| `TIMEFRAME` | `5m` | таймфрейм свечей |
| `EMA_FAST` / `EMA_SLOW` | `9` / `21` | периоды скользящих средних |
| `RSI_PERIOD` | `14` | период RSI |
| `RSI_OVERBOUGHT` | `70` | выше — сигналы на покупку игнорируются |
| `TRADE_SIZE_FRACTION` | `0.1` | доля свободного USDT на одну сделку |
| `STOP_LOSS_PCT` | `1.5` | стоп-лосс, % от цены входа |
| `TAKE_PROFIT_PCT` | `2.5` | тейк-профит, % от цены входа |
| `PRICE_CHECK_INTERVAL_SEC` | `30` | частота проверки стоп-лосса/тейк-профита |

## Ограничения этой простой версии

- Состояние позиции хранится в локальном файле `state.json` — если Railway пересоздаст
  контейнер без подключённого volume, состояние обнулится (бот подумает, что позиции нет,
  хотя монета может остаться на балансе). Для 1 бота на 1 паре это редкий и не критичный случай,
  но для более серьёзного использования стоит вынести состояние во внешнее хранилище (например,
  Railway Postgres/Redis).
- Стратегия однонаправленная (только лонг), т.к. это спот — шорты на споте не делаются.
- Нет бэктестинга "из коробки" — перед реальными деньгами имеет смысл прогнать логику на
  исторических данных отдельно.

## Локальный запуск (без Railway)

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполните своими ключами
python main.py
```
